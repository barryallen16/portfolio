tamil tokenizer

ai · rust
+36.9% vs mBERT
problem
General subword tokenizers (mBERT, Llama-3) fragment agglutinative Tamil into arbitrary byte shards, tripling sequence length, blowing KV-cache budgets, and corrupting 52% of Latin-1 decodes.
tradeoff
Writing a custom BPE training engine in Rust gained raw training speed, but required engineering merge tracking, CSR matrix indexing, and Hugging Face export tooling from scratch.
solution
1,135-token base vocabulary around Tamil conjunct stems, Aho-Corasick parallel merges with rayon, and CSR indexing. Achieved 0.9193 bits/byte on Tamil wiki (36.9% better than mBERT) with 100% decode fidelity.

triagemate

ai · security
12ms · 0.6594 AUC
problem
Static analysis tools like Semgrep generate hundreds of unranked alerts per codebase, burying exploitable security vulnerabilities beneath low-priority warnings.
why ai
Static AST rules lack execution semantic context. Determining whether tainted user input can trigger an exploit requires reasoning over commit diffs, sanitizers, and control flow.
tradeoff
Fine-tuning on 416 real pre/post-fix diffs prevented synthetic benchmark collapse, but required statement anchoring to align unnumbered AST code snippets with line alerts.
solution
Fine-tuned Liquid AI d1-3B hybrid SSM with contrastive LoRA to rank alert exploitability in 12-14 ms on an Nvidia T4. Reached 0.6594 within-rule AUC and 0.8000 on Vul4J real CVEs.

fitcheck

IEEE 2026 · 3.1x VRAM
problem
Multimodal outfit recommendation models require heavy cloud GPUs, but uploading personal wardrobe photos violates user privacy and fails without internet access.
why ai
