tamil tokenizer

ai backend
problem
general-purpose subword vocabularies shatter tamil into far too many pieces, so tamil corpora cost more tokens and train slower than english ones.
tradeoff
hand-writing bpe in rust instead of building on sentencepiece or huggingface tokenizers. that bought the speed and cost me the ready-made training loop.
solution
247 tamil character clusters as base tokens, aho-corasick multi-pattern encoding, rayon-parallel bpe training. 11-16x faster than sentencepiece, 32k vocab on huggingface, 23 tests on every merge.

sivabharani comments

ai backend
problem
sb us answers subscriber questions inside 2,000+ youtube videos. nobody could search their own name to find the one video where he answered them.
tradeoff
an llm pass over every transcript chunk instead of search alone. that narrows the index and costs a full run over 1.18m chunks, and youtube's english auto-transcripts were too broken to trust, so the model had to carry the work.
solution
2,755 videos scraped, 1,185,665 chunks run through local gemma 4-bit inference to keep only the ones naming a person. search a name, get the video and the timestamp. dataset on huggingface.

java vulnerability checker

ai backend
problem
static analyzers miss sql injection, xss and insecure deserialization, and general code models had no idea what a vulnerable java pattern looks like.
tradeoff
budget on dedup instead of parameters. the 7b beat my 14b run, 80.39% against 78.43% on the same 102 cases, which says the merged corpora were dirtier than they needed to be.
solution
seven pipeline stages from raw jsonl to conversation-formatted sft, sha256 dedup on normalized lines, lora fine-tune, then a fixed 102-case eval any checkpoint runs through one function call. weights on huggingface.

kaggle automation

backend ai
problem
kaggle sessions expire after 12 hours, so a training run that outlasts one is gone, and watching that by hand means babysitting a browser tab.
tradeoff
pooling nineteen accounts and sharding one job across them instead of waiting out a single session. 223 runs' worth of gpu hours, paid for in credential handling and retry logic.
solution
a dockerized fastapi control plane on ec2 that pools api keys, shards jobs across accounts, and alerts on the 12-hour cutoff. github actions runs uv sync, ruff and pytest over 12 test suites.
source

fitcheck

frontend ai ui/ux
problem
fashionclip runs in the browser but it can't reason about an outfit, only match an image to a garment. a shopping site needs the reasoning and can't afford a server-side model doing it.
tradeoff
distilling a vision-language teacher into a student that still runs client-side. the student keeps 91.6% of teacher quality and runs 21% faster on 3.14x less vram, and reasoning that came free from the 8b teacher now comes from a 2.9k-example tuning run.
solution
qwen3-vl-8b labeled 106k fashion photos, which became 538k caption-and-qa pairs for perception tuning, then 2,923 recommendations with written rationales for reasoning tuning. evaluated two ways: a 1,000-image bench and a blind human study over 297 ratings. first-author ieee paper, model and three datasets on huggingface.
paper pdf source

moviemod scraper

backend
problem
a site that rotates its domain and hands out per-access download tokens, so a scraper works for a week and any link it stores is dead by evening.
tradeoff
selenium plus a mysql mirror over a plain http fetch. heavier to run and to maintain, and the stored rows are a snapshot of one afternoon, not a permanent copy.
solution
resolves the live domain on each run, multiprocess workers with retry and backoff, mysql dedup so a re-run doesn't duplicate rows, docker compose, and telegram alerts on failure. a stored link that 404s gets re-scraped instead of debugged.
source
